# Задача 4.1 — KV-сервер с подпиской в трёх моделях конкурентности: потоки, Ractor, процессы

**Тема:** 4. Клиент-серверное взаимодействие  
**Язык программирования:** Ruby  
**Ветка для реализации:** `4_task_1_ruby`

## Общая задача темы

Задача темы: сетевое KV-хранилище с подпиской на изменения. Для всех вариантов определяется общий протокол взаимодействия.

## Постановка задачи

Один и тот же протокол реализуется тремя способами: поток на соединение с учётом GVL в стандартной реализации Ruby, шардированное хранилище на Ractor-ах с настоящим параллелизмом и пул процессов с мультиплексированием внутри. Жизненный цикл соединения описывается блоком с гарантированным освобождением подписок, что сравнивается по объёму кода с RAII в C++ и контекстным менеджером в Python. Итог — сравнение производительности и особенностей GVL в Ruby и GIL в CPython на одинаковой сетевой нагрузке.

## Общие условия

- Реализовать основную логику на указанном языке, не используя специализированные библиотеки с готовой реализацией задачи.
- Использовать штатные возможности языка и его платформы для необходимых операций.
- Проверять корректность реализации на тестовых данных. Сравнительные эксперименты и эталоны, указанные в постановке, относятся к этой задаче.
